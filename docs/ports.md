## Dynamic Port Allocation

If a preferred port is occupied, HIRIS automatically allocates the next available port.

### How It Works

```
scripts/portals.config.js
        │
        ▼  preferred ports
scripts/find-ports.js
        │
        │  1. For each portal, open a TCP socket test on preferred port
        │  2. If free → use it. If occupied → try preferred+1, +2, ...
        │  3. Write all resolved ports to:
        ▼
scripts/.resolved-ports.json   (auto-generated, gitignored)
        │
        ▼
scripts/inject-env.js
        │  Reads .resolved-ports.json
        │  Writes apps/frontend/.env.<portal> (with correct VITE_DEV_PORT
        │         and all VITE_PORTAL_URL_* cross-portal redirect URLs)
        │  Writes scripts/.allowed-origins.txt (for backend CORS)
        ▼
start_all.sh / start_all.bat
        │  Exports ALLOWED_ORIGINS env var
        │  Launches backend + each Vite portal with --port <resolved>
        ▼
Terminal prints resolved URL table
```

### Example: Port Conflict Scenario

Suppose port 5176 (CHRO) is already in use by another app:

```
[PORTS]  Allocating ports...
  ✓  Backend API            :3001
  ✓  Landing Page           :5173
  ✓  Faculty Portal         :5174
  ✓  Hiring Mgr Portal      :5175
  ⚡  CHRO / Admin Portal    :5179  (wanted :5176)   ← auto-reallocated
  ✓  Recruiter Portal       :5177
  ✓  Candidate Portal       :5178
```

The CHRO portal starts on `:5179`. All other portals' `VITE_PORTAL_URL_CHRO` env var is automatically updated to `http://localhost:5179` so cross-portal redirects still work.

## Changing Default Ports

Edit **`scripts/portals.config.js`** — this is the **only file** you need to change:

```js
// Change CHRO from 5176 to 4000:
{ id: 'chro', label: 'CHRO / Admin Portal', preferred: 4000, ... }
```

Re-run `bash start_all.sh`. All `.env` files and the backend CORS list are regenerated automatically.

**Never hardcode ports** in:
- `apps/frontend/.env.*` — these are auto-generated
- `apps/backend/.env` → `FRONTEND_URL` — replaced by `ALLOWED_ORIGINS`
- Vite configs — these read `VITE_DEV_PORT` from the generated `.env.*`

## CORS & Origins

`scripts/.allowed-origins.txt` is auto-generated and contains:
```
http://localhost:5173,http://localhost:5174,http://localhost:5175,http://localhost:5176,http://localhost:5177,http://localhost:5178
```

The backend reads this at startup via the `ALLOWED_ORIGINS` env var (exported by `start_all.sh`). In development, all `localhost:*` origins are also permitted as a fallback (regex match in `isAllowedCorsOrigin`).

## Adding a New Portal

1. Add an entry to `scripts/portals.config.js`:
   ```js
   { id: 'admin', label: 'Super Admin', preferred: 5180,
     config: 'vite.config.admin.js', mode: 'admin' }
   ```

2. Create `apps/frontend/vite.config.admin.js`:
   ```js
   import { createPortalConfig } from './vite.config.base.js'
   export default createPortalConfig({ portal: 'admin', port: 5180, htmlFile: 'admin.html', outDir: 'dist/admin' })
   ```

3. Create `apps/frontend/admin.html` (copy `chro.html`, change entry script path)

4. Create `apps/frontend/src/portals/admin/main.jsx` and `AdminRoutes.jsx`

5. Run `bash start_all.sh` — port is allocated automatically.
