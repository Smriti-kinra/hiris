# HIRIS — Startup System

## Quick Start

```bash
# macOS / Linux
bash start_all.sh

# Windows
start_all.bat

# npm shortcut (any platform)
npm run start:all
```

---

## Startup Sequence

```
bash start_all.sh
       │
       ▼
[STEP 1/4]  node scripts/find-ports.js --kill
       │     ├─ For each portal in portals.config.js:
       │     │     test if preferred port is free via TCP socket
       │     │     if occupied → kill the process, wait 0.4s
       │     │     find next free port (preferred, +1, +2, ...)
       │     └─ Write scripts/.resolved-ports.json
       │
       ▼
[STEP 2/4]  node scripts/inject-env.js
       │     ├─ Read scripts/.resolved-ports.json
       │     ├─ Regenerate apps/frontend/.env.<portal> for each portal
       │     │     sets VITE_DEV_PORT, VITE_API_BASE_URL, VITE_API_ORIGIN
       │     │     and all VITE_PORTAL_URL_* cross-portal redirect URLs
       │     ├─ Regenerate apps/frontend/.env (landing base env)
       │     └─ Write scripts/.allowed-origins.txt
       │           (comma-separated http://localhost:<port> for each portal)
       │
       ▼
[STEP 3/4]  Read resolved ports from .resolved-ports.json
       │     Export ALLOWED_ORIGINS env var for backend CORS
       │     Print service URL table
       │
       ▼
[STEP 4/4]  npx concurrently [all services]
       │     ├─ [backend]   cd apps/backend && npm run dev
       │     │              (reads ALLOWED_ORIGINS from env)
       │     ├─ [landing]   npx vite --port 5173
       │     ├─ [faculty]   npx vite --config vite.config.faculty.js --mode faculty
       │     ├─ [hiring]    npx vite --config vite.config.hiring.js --mode hiring
       │     ├─ [chro]      npx vite --config vite.config.chro.js --mode chro
       │     ├─ [recruiter] npx vite --config vite.config.recruiter.js --mode recruiter
       │     └─ [candidate] npx vite --config vite.config.candidate.js --mode candidate
       │
       ▼
All services running. Terminal shows color-coded logs per service.
Ctrl+C kills all processes simultaneously (--kill-others-on-fail).
```

## How Each Vite Portal Reads Its Env

Vite loads env vars in this priority order:
1. `.env.{mode}` (e.g. `.env.chro` for `--mode chro`)
2. `.env`
3. System environment

Because `inject-env.js` regenerates `.env.chro`, `.env.faculty`, etc. **before** Vite starts, each portal always reads the correct resolved ports.

**Example: `.env.chro` after dynamic injection:**
```
# CHRO / Admin Portal — Auto-generated by scripts/inject-env.js
# DO NOT EDIT MANUALLY — regenerated on every start_all.sh run

VITE_PORTAL_ID=chro
VITE_PORTAL_LABEL=CHRO / Admin Portal
VITE_DEV_PORT=5176
VITE_API_BASE_URL=http://localhost:3001/api
VITE_API_ORIGIN=http://localhost:3001

# Cross-portal redirect URLs
VITE_PORTAL_URL_LANDING=http://localhost:5173
VITE_PORTAL_URL_FACULTY=http://localhost:5174
VITE_PORTAL_URL_HIRING=http://localhost:5175
VITE_PORTAL_URL_CHRO=http://localhost:5176
VITE_PORTAL_URL_RECRUITER=http://localhost:5177
VITE_PORTAL_URL_CANDIDATE=http://localhost:5178
```

## Dynamic Port Injection Flow Diagram

```
scripts/portals.config.js       ← Human-editable. Source of truth.
          │ preferred ports
          ▼
scripts/find-ports.js           ← TCP socket tests each port
          │ resolved ports
          ▼
scripts/.resolved-ports.json    ← Machine-generated. Gitignored.
          │
          ▼
scripts/inject-env.js           ← Writes all .env files
          │
          ├──► apps/frontend/.env.faculty    VITE_DEV_PORT=5174
          ├──► apps/frontend/.env.hiring     VITE_DEV_PORT=5175
          ├──► apps/frontend/.env.chro       VITE_DEV_PORT=5176
          ├──► apps/frontend/.env.recruiter  VITE_DEV_PORT=5177
          ├──► apps/frontend/.env.candidate  VITE_DEV_PORT=5178
          ├──► apps/frontend/.env            VITE_DEV_PORT=5173
          └──► scripts/.allowed-origins.txt  ← Backend CORS list

start_all.sh
          │ exports ALLOWED_ORIGINS from .allowed-origins.txt
          │ reads resolved ports from .resolved-ports.json
          │ passes --port <resolved> to each vite instance
          ▼
concurrently launches all 7 services simultaneously
```

## Scripts Reference

| Script | Command | Purpose |
|--------|---------|---------|
| `find-ports.js` | `node scripts/find-ports.js` | Resolve free ports |
| `find-ports.js` | `node scripts/find-ports.js --kill` | Kill stale + resolve |
| `inject-env.js` | `node scripts/inject-env.js` | Regenerate all .env files |
| `start_all.sh` | `bash start_all.sh` | Full startup (macOS/Linux) |
| `start_all.bat` | `start_all.bat` | Full startup (Windows) |

---

## Crash Handling

- `--kill-others-on-fail` flag on `concurrently` means if **any** service crashes, all others are stopped automatically
- To restart: `bash start_all.sh` — stale processes are auto-killed and fresh instances start
- To stop manually: `Ctrl+C` in the terminal running `start_all.sh`
